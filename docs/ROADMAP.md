# 优化路线与实现可行性

以下“实现可能性”是基于当前 Electron、TypeScript、SQLite 和蒙特卡洛架构的工程估算，不代表数据提供商一定开放相应数据。

## 已在 v0.2.0 实现

| 优化项 | 用户价值 | 状态 |
| --- | --- | --- |
| 导入比赛生成历史校准方案 | 让事件和追踪数据真正进入球员倾向与置信度，而不只是存档 | 已实现 |
| 分层样本平滑 | 低样本球员回退到位置先验，避免小样本被放大 | 已实现 |
| 流式蒙特卡洛聚合 | 运行大批量回合时不长期保存全部中间对象 | 已实现 |
| 双向进攻坐标 | 客队持球时向左推进，正确计算射门目标、禁区和左右通道 | 已实现 |
| 导入安全校验 | 限制文件体积、预览有效期、坐标范围和非法数值 | 已实现 |
| 球员搜索与历史样本显示 | 更快定位球员并理解置信度来源 | 已实现 |

## 推荐下一阶段

| 优先级 | 方向 | 实现可能性 | 预计难度 | 关键条件 |
| --- | --- | --- | --- | --- |
| P0 | 多场比赛聚合先验 | 高，约 90% | 中 | 增加球员跨比赛身份匹配、时间衰减和联赛/位置分层平滑 |
| P0 | 从具体事件或 360 快照创建起始情景 | 高，约 90% | 中 | 增加比赛事件时间线、快照选择器和阵容映射 |
| P0 | 控球转换与攻防连续回合 | 高，约 80% | 中高 | 当前引擎以单次进攻回合为边界，需要增加球权状态机 |
| P1 | 暂停、进度与多 Worker 并行 | 高，约 85% | 中 | 将迭代拆成批次并合并统计量；适合 10,000 次以上实验 |
| P1 | 真实热点图和传球网络可视化/PNG 导出 | 高，约 95% | 中 | 已有坐标和传球边数据，主要工作在渲染与导出 |
| P1 | 定位球、界外球、角球模板 | 高，约 85% | 中 | 增加情景模板、禁区盯人和第一/第二落点规则 |
| P1 | 数据源赛事/赛季浏览器 | 高，约 85% | 中 | 完成 `DataProviderAdapter` 的列表界面、缓存和限流处理 |
| P2 | 连续无球跑位与体能模型 | 中，约 65% | 高 | 最好具备稳定的逐帧追踪数据；需要时间步进和碰撞/空间约束 |
| P2 | 参数校准与回测工作台 | 中高，约 75% | 高 | 需要训练/验证比赛拆分、评分函数和批量实验管理 |
| P2 | 自动更新与代码签名 | 高，约 95% | 中 | 自动更新可直接实现；消除 SmartScreen 警告需要商业签名证书 |
| 可选 | AI 摘要与自然语言解释 | 高，约 90% | 中 | 保持为可禁用插件；不得进入任何核心概率计算链路 |

## 推荐顺序

1. 先完成“多场聚合先验”和“从 360 快照创建情景”，让数据价值和实际工作流完整闭环。
2. 再增加连续攻防状态机、进度和多 Worker，使实验更接近真实战术阶段并支持更大批量。
3. 随后完善定位球、图形导出、参数回测和提供商浏览器。
4. 连续物理跑位、自动更新、代码签名和 AI 扩展作为独立模块推进，避免干扰离线核心。

## 模型边界

- 事件数据可以可靠校准有球倾向，但不能独立证明无球跑位和防守站位。
- 热点图图片只作为参考叠加，不应从像素反推训练坐标。
- 商业数据源能否提供球员坐标、速度或压力数据取决于订阅许可，适配器实现成功不等于数据覆盖可用。
- 所有输出继续标记为概率分析，不将结果描述为真实比赛预测。
